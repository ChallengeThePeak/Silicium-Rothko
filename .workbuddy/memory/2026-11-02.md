- 走官方构建链：`DeviceBuild.py` + `stuart`，无旁路。踩过的坑：
  1. `mu_nasm` 包在 ProjectMu 的 Azure feed 上，本机连不上（curl 000）→ 用户代下后
     放进 `~/.nuget/packages/mu_nasm/20016.1.1/`，stuart 走本地缓存命中。
  2. 无 root 的 mono：apt 下载 deb 解包到 `~/mono`，需 `MONO_CFG_DIR=~/mono/etc`，
     否则 NuGet.exe 报 `System.Native` / `System.ComponentModel.Composition` 缺失。
  3. `Platforms/Xiaomi/rothkoPkg/Include/DXE.inc` 与 `APRIORI.inc` 同名，`Unicorn` 冲突。
- 相对上游共改了 6 处（均已写注释 + 备份在 `~/quarantine/`）：
  1. `MemoryMapLib.c`：资源描述符属性 `SYS_MEM_CAP_XN` → `SYS_MEM_TESTED`
     （Gcd.c 要求掩码后**恰好等于** P|I|T，能力位会让它断言）。
  2. `MemoryMapLib.c`：内存表裁到 3 GiB（删 ≥0xC0000000 的 9 段）。3–4 GiB 段
     访问会报 address size fault，裁掉后 DXE 一路到 BDS。
  3. `FrameBufferSerialPortLib.c`：`FbRegion` 未初始化 + 越界刷缓存 → data abort/递归异常。
  4. `APRIORI.inc`：移出 BdsDxe（APRIORI 优先调度，会跑在 HiiDatabaseDxe 之前）。
  5. `rothko.dsc`：`PcdDriverHealthConfigureForm` 设全零，跳过健康检查（无 SetupBrowserDxe）。
  6. `UniXNUConfig.dsc.inc`：注释两条未在任何 DEC 声明的 PCD（EDK2 error F001）。
- 取日志的坑（都很费时间）：
  - pstore 在 DRAM `0x48090000+0xE0000`；内核 ramoops 按 cmdline
    `mem_address=0x48090000 console=0x40000 pmsg=0x80000` 布局。
    上游固件写 pmsg 到 `0x480F0000`（=base+0x60000），**实测可读**，别改。
  - PSCI SYSTEM_RESET 在这台机器上等价冷启动 → DRAM 被清 → pmsg 丢失；
    **只有看门狗超时复位能保住 RAM**。所以 BDS 末尾只能停住等 WDT，别主动复位。
  - `console-ramoops-0` 每次开机都被内核刷新，存在≠RAM 存活。
  - expdb(128 MiB) 只有末尾 2 MiB 是 MTK 配置描述串；blackbox(154 MiB) 只有
    boot_tag/kedump；pstore 分区(133 MiB) 全零。**固件日志只可能在 DRAM**。
