# 裁表后异常迁移到 4 GiB 附近（2026-11-02）

## 结果
裁表生效：`MMU: 41 regions`（原 43），GCD 中 13 GiB 两段消失，最高只剩 `0xFFFFF000 len 0x1000`。
GCD `Found=1`，DXE 继续加载到 `UniXNUDxe`。

## 新异常
```
ELR 0x40E5FE0C (DxeCore+0x3E0C) = InternalMemCopyMem (CopyMem.c:85)
调用链: PeCoffLoaderLoadImage <- CoreReadImageFile <- CoreLoadImageCommon
FAR 0xF9FBFFF8   ESR 0x92000000 (EC=0x24, ISS=0 -> address size fault, level 0)
SPSR 0x20000205 (EL1h)
```

`0xF9FBFFF8` 落在 `RD 0xF9280000 + 0xD80000`（约 3.9 GB），**仍在已登记的内存表里**。
上一轮 `ResetSystemRuntimeDxe` 也被装到 `0xFD880000`（3.96 GB）。

## 观察
- 两次失败都在 **最高的 1 GB 区间（0xC0000000 以上）**，低区从未出错。
- SEC 时刻实测 `T0SZ=0x18`（40 位 VA）、`CurrentEL=0x4`、`L0[0]` 有效。

## 下一步（本版镜像）
在 DXE 异常处理里补打异常发生时刻的 `CurrentEL/SCTLR/TCR_EL1/TTBR0_EL1/T0SZ`，
与 SEC 时刻比对：

- 若一致（T0SZ=0x18）→ 是页表在该区间缺项，需要看 L1[3] 的构建；
- 若不同（TCR 被改小或 TTBR0 被换）→ 抓出改动者。
